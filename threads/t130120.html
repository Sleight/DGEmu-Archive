1. Emulators [EMUS]
There are many GBA emulators available for use. The following are the ones recommended by DGEmu:

Official site: http://vba-m.ngemu.com/
Latest version: SVN 926 (Windows)

VBA-M is the official successor to VBA with the goals of improving performance, fixing bugs, and expanding the capabilities of VBA to include features of the various available forks. Many respected emulator developers have contributed to the project, including Spacy (VisualBoyAdvance-S), Mudlord (Rice Video, Glide64), Nach (ZSNES), Blargg (ZSNES), and Jonas (ZSNES).

2. Save Settings
Certain games require specific save settings that need to be set manually. Otherwise, errors in in-game (battery) saves may occur or "white screens" may be encountered during emulation.

The best solution is to place a vba-over.ini configuration file in the same directory as your emulator. This file automatically configures the save type settings for most common games. For the file to work, the default save settings must be set (go to Options -> Emulator -> Save Type -> Automatic and Options -> Emulator -> Save Type -> Flash 64K). If you have existing save files, you may need to delete, move, or rename them to allow the save configuration to work.

3. Specific Rom Issues [ROMI]
The Classic NES and Famicon Mini roms do not work properly on VBA/VBALink; however, they do work properly on VBA-M when a proper vba-over.ini file is used (see above). To play them on VBA/VBALink, please download WRG's "Famicom Mini & Classic NES crackedpack" (mirror)

There are certain roms that are known to not work on emulators. At the moment, these include the following:
Madden 2006 and Madden 2007 (plays don't show up on screen)
Action Replay roms (requires hardware support - use the emulator's built-in cheat engine instead)
GameShark roms (requires hardware support - use the emulator's built-in cheat engine instead)
CodeBreaker roms (requires hardware support - use the emulator's built-in cheat engine instead)
MP3 Player roms (requires hardware support)

5. BIOS Errors
If you are using VBA-M, there should be no BIOS errors if you are using a proper vba-over.ini file (see above).

Certain games use GBA BIOS functions that are not emulated by VBA/VBALink. When this occurs, you get an error message that says something like: "Unsupported BIOS function 0d called from 080f220a. A BIOS file is needed in order to get correct behavior."

To solve this problem, download a copy of the BIOS and use it. You can download a copy of the BIOS here:
http://www.megaupload.com/?d=OTQ5XSHZ

To use the BIOS, go to Options -> Emulator -> Select BIOS file... and choose the BIOS file that you downloaded (you may need to type in the filename manually if the file extension isn't recognized). Then go to Options -> Emulator -> Use BIOS file to enable it.

6. Speeding up emulation

First of all, consult the official VBA FAQ for tips on making the emulator run faster: http://vba.ngemu.com/faq.shtml#cat6_2

If those fail to solve your problem, you may also want to decrease your screen resolution or color quality. In Windows, right-click your desktop and choose Properties. From there, lower your screen resolution (you may need to click on the "Settings" tab) and/or your color quality.If you are using VBA-M, emulation may be choppy when using OpenAL or Xaudio. This is caused by an overly short buffer; adjust the size appropriately for your system. NOTE: If you are using a Creative sound card, choose OpenAL and select the name of your sound card in the device list.
