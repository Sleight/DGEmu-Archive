The only time you should set DGEmu in developer mode is only when you want to enable hook export into HTML for development purposes. Once your hook as been exported, make sure to set DGEmu back in normal mode.

IP.Board 3 includes a useful 'developer mode' that facilitates easier skin and language management, as well as a few additional tools and settings in the Admin Control Panel. There are a few steps you must take in order to enable the developer mode in IP.Board.If you are using IP.Board 3.1.0 or newer, you can make use of the command line tool to build these files and directories. Simply upload the file 'buildInDev.php' from the 'tools' directory of the download ZIP into your forums root directory and run it via command line (php buildindev.php) and then follow the onscreen prompt.Note that this requires SSH access if you're not running from your local computer.

Step 1 The first thing you must do is edit conf_global.php. In conf_global.php find

define( 'IN_DEV', 0 );

and change to

define( 'IN_DEV', 1 );

If the first line does not exist in your conf_global.php (e.g. because you upgraded) simply add the second line before the closing php tag. If you wish to switch on PHP error reporting on screen while developing and testing your code, you should also add this line to your conf_global.php

ini_set('display_errors',1);

Step 2 While in developer mode, IP.Board loads language files from a special directory that won't exist on a base install.
Go to cache/lang_cache and make a copy of the entire '1' folder, and rename the copy 'master_lang'. You should now have a populated cache/lang_cache/master_lang directory that contains all of the normal language files. When you need to add your language file, create it in the master_lang folder you just created and edit it in the same fashion as the other language files in this folder. When you are ready to build your application for release, use the developer tool in the ACP under the Look & Feel tab -> Manage Languages. Under 'Select the application language files to import' select your application and click Import, and then after the import is done, click Export next to 'Export language files to application directories'. Note that language files are tied to an application based on the first part of the language file name. For instance with a language file named 'core_public_key.php', the application would be 'core', the language file would be a public language file, and using the key 'key'. To load a language file in your application you use the following code

ipsRegistry::getClass('class_localization')->loadLanguageFile( array( 'public_key' ), 'core' );

The first argument is an array of language file names (without the application bit, and without the .php suffix), and the second argument is the application to load the language files from. If the second argument is omitted, IP.Board assumes the language file is part of the currently loaded application.

Step 3 While in developer mode, IP.Board uses a special skin set that has special functionality (e.g. the ability to import the skin template bits into the admin CP). To create the special skin set login to the admin control panel and go to the Look & Feel tab, then click on Template Tools in the left hand menu. Scroll down to find 'Create Master PHP Templates Directory' and click on 'Run' next to this. This will create a cache/skin_cache/master_skin/ directory with all of the current skin files cached to it, but in the IPB HTML logic format you would expect to see in the admin control panel, rather than in the normal 'cached' format (standard PHP code) you would see in any other skin. When you add a new skin file to this directory, or add skin template bits to existing skin files, you should use 'HTML logic' and not raw PHP code, just as you would normally enter in the admin cp. When you are ready to build your application for release, you can use the developer tool on the same page labeled 'Build Skin Files For Release' in order to import the skin files and export the appropriate XML files for your application. To call a skin template in your application you would use the following code

$this->registry->output->getTemplate('skinname')->templateName( $arguments );

'skinname' is the skin file name, without the 'skin_' prefix or the '.php' suffix (e.g. 'skin_skinname.php' in the example above). If the skin file has not previously been loaded, it will be auto-loaded on the fly. templateName is the template bit name in the skin file and $arguments are any arguments you need to pass to the template bit.

Step 4: Using Master CSS When in_dev, the way the css is called is through direct calls to the stylesheets. To use the master_css:Go to public/style_css/Make a copy of the css_1 directory, and rename the copy to master_css. You will then need to edit most of the files in the new master_css directory, inserting a code block at the top of the file.Here is an example of the block which would need to be inserted in the 'ipblog' file. Following this example are the details needed to edit each specific file.
