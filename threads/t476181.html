KKirie MotobaMay 25 2012, 10:44 PM
For a slipstreamed copy, you need to figure out something first:

Your Windows XP key, is it a retail or oem? (retail is basically a nice Windows XP box with instruction manual, a cd-key, and the disc sold in retail stores, oem copy is often in a simple envelope, and either is bought from a store that builds computer for u, a digital download or order from Microsoft, or the tag is on a computer with a disc given by the manufacturer (found on laptops and desktop made by Acer, Hp, Toshiba, etc).

Once you figured that out, you should be on the lookout of files online based on the disc's volume label names.
That being said, the 2 volume labels that would interest you:
Retail Home with SP3: GRTMHFPP_EN
OEM Home with SP3: GRTMHOEM_EN

Doing a search with these should give you a few torrents and stuff here and there. If it doesn't work out, you can always go about it this way:

Install with your SP1 disc.
Have a custom disc with all the big patches copied on them.
In other words:
XP Service Pack 2: http://www.microsoft.com/en-us/download/details.aspx?displaylang=en&id=28
XP Service Pack 3: http://www.microsoft.com/en-us/download/details.aspx?displaylang=en&id=24
Internet Explorer 8: http://www.microsoft.com/en-us/download/details.aspx?id=43
Windows Media Player 11: http://www.microsoft.com/en-us/download/details.aspx?id=8163
.NET Framework 4: http://www.microsoft.com/en-us/download/details.aspx?id=24872

By at least having those handy on a disc, you will avoid the issue of downloading and installing useless patches for previous versions of software and will save you lots of time. What you would do is simply install Windows with your disc, then apply SP2, then apply SP3, then apply IE8, WMP, and finally .NET.

KKirie MotobaMay 14 2013, 05:23 PM

IT, software packager and SMS 2003 administrator.

Most people will simply go: wtf does that do in life?

 

Software packager:

Compiling windows installer from a variety of sources (I was doing that as a hobby for my Touhou Project games and stuff, and that's actually how it got me this job) and transforming existing installers so that they are preconfigured and can be installed silently in a company infrastructure.

 

2 examples of transforming an existing installer:

- Java that you guys download off the web, click next a few times to install it, then manually go configure it to your tastes, I take that same installer, apply modifications so that Java is installed already configured the way I want, and call up a command so that the user doesn't see anything, it just installs.

- Microsoft Office that you guys insert the CD, enter product key, choose what features you want, and once installed, apply service pack, and all updates, I create a copy of Office with the product key integrated, all the features preset, and all service packs and updates streamlined in the same installer, and again, all run silently without the user needing to press any buttons.

 

Why do that? It's to compliment my second task being the SMS 2003 administrator:

- Take that same package and decide under which locations of the network I want it to be pushed to. Once done, I schedule an installation say at night at 9PM: Java and Office will be installed on say 5000 workstations in 1 shot, all I need to do is verify installation status and troubleshoot the failures if needed. Software deployment.

 

Asides from that, I also have these roles as SMS administrator:

- Inventory of all workstation and servers detected on network, including their hardware specs and software, and create reports.

- Report anything out of the normal: Users installing utorrent and such are caught and reported, software being wrongfully pushed, etc.

- And the usual maintenance and troubleshooting of any infrastructure.

 

And I just realized I am explaining too much on a forum that will probably result in a tl;dr.

For Office 2003, you had a tool to transform the MSI installer.

 

Since Office 2007, the new Office Customization Tool is integrated into the setup, you have to launch it as admin to compile the MSP to apply your preferences. It also made it much easier to configure a multi-language Office setup (my environement requires an Office that has both French and English, auto-configured to the language of the system). There's an XML file that needs to be modified, along with the OCT that needs to be run.

Office is the easiest one to prepare (most Microsoft products actually, SQL Management Studio 2008, and other such are as easy), and most of the time, a Windows Installer in MSI format is straightforward (as long as you know what property needs to be assigned to customize the software). Adobe software also have their own setup customization tools.

 

What complicates things is old products, things still using the old setup standard (recording a setup ISS response file) but that wasn't of the norm, recapturing product installations, etc. And the biggest of all challenges: setting security rights to the application (remember, an office is locked down, users can't write to many sectors of the computer for security purposes. We needs to identify what files must be allowed to be updated in order for the app to not crash, and give write and update access to specific groups of people with specific credentials.)

 

And what you have to consider also is that even though the package works perfectly with my admin credentials, it doesn't mean deploying it by SMS2003 (or SCCM) will work either since that will use SYSTEM context credentials (a package that requires a connection to a database on the network to validate info and customize will not work since SYSTEM is a local admin and not a domain admin like myself).

 

And nowadays, I'm working with VMWare Thinapps, pretty cool. (Think of it as the same as the portableapps you get off the Internet, once compiled, it's a single file to run and will have a fully working application loaded up)
