Impact Tremor' post='4479714 wrote on Jan 2 2009, 11:44 PM:
It's just that this statement bothers me. How else would you identify an internet user? It's not like you can have face-recognition servers or online DNA tests.
Eh, I don't think you quite understand what SSL certificates are used for. SSL certificates are used to identify a machine (namely, the one hosting the site that you're visiting). If the certificate is valid, then your machine and the remote machine exchange encryption/decryption keys that are used to encrypt/decrypt transmissions to and from the site. User identification is a completely separate issue. In any case, there's no real way of identifying an Internet user in any form anyway. The Internet is built on a trust system, which assumes that things like DNS servers are working properly and are not disseminating bad data. That's precisely why there's been a lot of talk recently about exploits that could potentially take down the entire Internet just by exploiting that trust system (i.e. by manipulating important middlemen servers).Regarding IP addresses and other forms of identification, there's no real foolproof way of identifying a user anyway. You can log raw HTTP request headers (which will probably give you as much information as you can possibly extract from the user involuntarily) and you would still easily end up with duplicates.I still don't think that just adding a password will really "fix" things, especially since you're using one master password for everyone. Assuming someone does get in, the job of figuring out who did it doesn't become any easier, and more importantly, there's still no provision for restoring the previous state. I'm not saying that there shouldn't be a password, but I am saying that adding a password would probably address a less pressing issue at the expense of more pressing ones.
